First, get this straight: game UI serves information, not layout Positioning

The first goal of game UI is to let the player read the current state within 0.2 seconds; looking good comes second. Any UI that blocks the view, or forces the player to dig three levels deep through menus before they can act, is a failed UI.

  • Safe area: leave room for notches / punch-holes (44–59dp at the top), rounded corners and the bottom gesture bar (34dp); don't push the health bar right up against the edge.
  • Put the core action zone inside the natural thumb arc (bottom-left / bottom-right), not in the middle of the screen.
  • Keep the HUD footprint within 20–25% of the view and leave the rest to the game scene.

HUD layering: classify first, then position Layering

LayerContentKey points
BackgroundSemi-transparent panels, gradient masksOpacity ≤ 30%, never steal the scene
InformationHealth, ammo, timer, resourcesFixed position, always visible, enough contrast
ActionSkill buttons, attack, jumpThumb-reachable, large hit areas, customizable
FeedbackDamage numbers, pickup prompts, large text calloutsShort dwell (< 800ms), doesn't cover key areas
  • Information-layer positions are always fixed: if health is top-left, it stays top-left forever; don't let it drift with the scene.
  • The feedback layer follows "fast in, fast out": appear fast, disappear fast, and never overlap itself.
  • Put a 1–2px outline or a dark gradient under important numbers so they stay readable on any background.

Numeric visualization: bars, segments and digits each have a use Numbers

  • Bars: for continuous values such as health and energy, where the intuition of "how much is left" matters.
  • Segments: ammo, charges, turn counts — discrete readability matters more than precision.
  • Digits: damage, coins, score; always use tabular-nums and add an outline.
  • Show lost health with a "delayed white bar"; it noticeably improves perceived clarity.
  • Add shape / icon cues on top of color: players with red-green color blindness can't tell "poison vs heal" apart.

Icon semantics: recognizable at a glance beats good-looking Icons

  • Skill / item icons are silhouette first: they only pass if a 48×48 source is still recognizable when scaled down to 40px (try a grayscale check).
  • The three states must be distinguishable: available / cooling down / unavailable — use desaturation + a semi-transparent mask + a countdown number.
  • Use the same icon for the same function across screens; "back" shouldn't be an arrow in one place and a cross in another.
  • Status icons (poisoned, burning, slowed) should look different from item icons to avoid confusion.
  • This repo's Game Icons (4,134 icons, CC BY 3.0) and the various UI sets can all be reused directly.

Menus: in-game and out-of-game are two different logics Menus

  • In-game menus (inventory, skill tree): reach the target within 2 clicks; support pause / semi-pause.
  • Out-of-game menus (hub, settings, shop): information density can be higher, but they need a stable hierarchy and a consistent back path.
  • For inventory grids, prefer an orthogonal grid + rarity outline + quantity badge + tooltip detail (hover / long-press).
  • Every screen needs at least one clear exit path; the "back" key must be correct for gamepad, keyboard and touch respectively.

Touch interaction: gestures need a fallback Touch

  • A floating virtual stick (spawns wherever the screen is touched) is friendlier than a fixed position; dead zone 8–12%.
  • Buttons ≥ 48dp, spacing between adjacent buttons ≥ 8dp; even small visual icons need large hit areas.
  • Handle multi-touch concurrency (move + shoot at the same time); document the finger-count limit in the instructions.
  • Long-press / drag / double-tap all need an equivalent explicit button; never make a gesture the only entry point.
  • Protect against edge false touches: swiping in from the bottom tray or the system gesture edge needs confirmation or a ≥ 12dp trigger threshold.

Color and feedback: systematize the "game feel" Feedback

  • Rarity colors follow convention: gray → green → blue → purple → orange/red; don't invent your own six-color system.
  • Buffs use warm bright colors + an upward float animation; debuffs use cool dark colors + shake / flash.
  • The hit-feedback trio: white flash + floating damage number + hitstop (30–80ms).
  • Screen shake needs an on/off switch and an intensity slider (players with motion sickness must be able to turn it off).
  • All feedback should wrap up within 300ms; GIF-style permanent light pollution wears people out.

Fonts: number readability is a hard requirement Fonts

  • Use monospaced / tabular figures for numbers (damage, coins), otherwise digits jump around; pixel styles need 8/16px alignment.
  • Use a sans-serif family for narrative text (rounded faces undercut seriousness); short button labels may use rounded faces.
  • Font budget: subsetting a common Chinese character set usually costs 1.5–3MB; for very large glyph sets consider bitmap fonts or system fonts.
  • At small sizes (≤ 14px) avoid light weights plus high stroke density; add an outline when needed to improve readability.

Onboarding: teach one thing before handing over the next Onboarding

  • Progressive: core actions use forced small steps, secondary features use passive hints (red dots / side tips).
  • Masked tutorials must be skippable, and must be findable again in the help center after skipping.
  • Teach gestures with animation instead of long paragraphs of text; one gesture at a time.
  • Don't pop five red dots at once: keep only one on the main path and put the rest into a "quests" list.

Multi-resolution, multi-language and localization Adaptation

  • 9-slice / vector first: stretch panels with nine-slice, prefer vector icons, and avoid cutting a separate PNG set for every resolution.
  • Test aspect ratios from 16:9 to 21:9 (and even 4:3 tablets): use anchors + safe area instead of hardcoded coordinates.
  • Reserve 30–40% extra space for text expansion (English into Russian/German); RTL languages need a mirrored layout.
  • Tier UI assets as @1x/@2x/@3x; low-end devices use the lower tier, don't always ship the highest resolution.
  • Highly saturated icons on a dark background turn into mush outdoors in bright light — remember to verify on a real device under sunlight.
