Start from the grid, not from the buttons Layout

Define the grid and spacing scale first, then pour content into it: with every size landing on the scale, a redesign won't collapse everything at once.

UseCompactStandardRoomy / touch
Base unit4px8px8px
Control height28–3236–4044–48

Block spacing162432–40
Max content width—1200–1280—
  • Use 12 columns for desktop up to 1440 and 16 columns for wide screens; use a 4-column grid on mobile.
  • Stick to a limited set of spacing steps (4/8/12/16/24/32/48) and write them as tokens: space.2 = 8px.
  • Don't mix compact and roomy within the same design; tool-oriented products lean compact, content and consumer products lean roomy.
Common pitfall: choosing spacing "by eye" instead of by scale, so a single page ends up with 10 / 11 / 13 / 14px spacing.

Density: information density is not the same as smaller text Density

Density is the amount of decisions a screen can carry, not the font size. Table-heavy admin panels aim for "see everything in one screen"; mobile aims for "one thing per screen".

  • Row height: compact 28–32px / standard 40px / touch 48px; leave at least 6px of vertical padding inside table rows.
  • Touch targets ≥ 44×44 px (iOS 44pt, Android 48dp); even if the visual button is only 24px, expand the hit area to 44.
  • In dense interfaces, grouping whitespace beats divider lines; whitespace is the cheapest separator in code.
  • Prefer tabular-nums (equal-width figures) for multi-column data, otherwise numbers jump sideways while scrolling.

Color: semantics beat good looks Color

Color is not decoration, it is a semantic signal: danger, success, warning and disabled must be distinguishable at a glance.

  • Practical ratio: background/neutral 60%, secondary 30%, accent 10%. Reserve the accent color for "the one thing you want the user to click".
  • Contrast thresholds: body text 4.5:1; large text (≥18.66px bold or ≥24px) and UI component boundaries 3:1.
  • Status colors must be paired with shape or copy — never rely on color alone, since around 8% of men have color vision deficiency (red-green being the most common).
  • Dark mode: use a slightly blue-tinted dark gray such as #0B0D17 rather than pure black; don't use pure white #FFF for text, #E8EBFF is easier on the eyes.
  • The monochrome icons in this repo are already normalized to fill="currentColor", so a single color: declaration restyles them with the theme.

Typography: hierarchy comes from contrast, not from piling on levels Typography

Keep the type scale to 5–7 steps: too many steps means no hierarchy at all.

  • Keep body measure to 45–75 characters (about 30–40 Chinese characters per line); beyond that readers lose their line.
  • Use system fonts for body text (PingFang / Microsoft YaHei / Noto Sans SC); don't ship an 8MB full Chinese webfont.
  • Normalize numbers, amounts and percentages with font-variant-numeric: tabular-nums.

Icons: one set is enough, don't mix three styles Icons

Mixing icon styles is the number one source of a cheap look. Pick one set (any of the 215 sets in this repo) and take everything from it.

  • Equal optical weight: on a 24px grid, square icons at 20px and circular icons at 22px in diameter look the same size (circles naturally read smaller).
  • Unify the stroke: one icon set may have only one stroke-width (commonly 1.5 or 2); don't mix in someone else's 1.25.
  • Keep only three sizes: 16 / 20 / 24; no 17px "just a bit bigger".
  • Icon + text gap is 8px; icon buttons need a hit area ≥ 40×40.
  • Any meaningful function needs an aria-label; purely decorative icons use aria-hidden="true" so screen readers don't repeat themselves.

States and feedback: never leave users wondering whether the click landed States

Every interactive element needs at least six states: default / hover / pressed / focus / disabled / loading.

  • Focus rings need ≥ 3:1 contrast and must not be clipped by overflow:hidden; apply :focus-visible only, so mouse clicks don't show them.
  • Operations under 300ms don't need a loading state; only use a spinner beyond 1s; for a list's first load, a skeleton screen is a far better experience than a spinner.
  • Toasts auto-dismiss in 3–5 seconds from a fixed position; 3 seconds is enough for success, while errors need enough reading time or a manual close.
  • The empty-state trio: what happened / why / what to do next. Writing only "no data" is just laziness.
  • Require confirmation for destructive actions (delete, clear), and put the dangerous verb on the button: "Delete permanently" rather than "OK".

Forms and validation: let users fill it right the first time Forms

  • Don't turn labels into placeholders — once filled, users can't tell what they typed. Labels above the field are the safest (left-aligned labels only for very narrow containers).
  • When to validate: validate on blur, don't shout "invalid format" as soon as the second character is typed.
  • Write error messages in plain language and offer a way out: "Invalid email format" → "Missing an @ — for example name@example.com".
  • Mark required fields with an asterisk plus aria-required; summarize form-level errors at the top and keep field errors next to their field.
  • Keyboard flow: Tab reaches everything, Enter submits, Esc closes overlays.

Accessibility is not an option, it is the quality bar a11y

  • Semantics first: a button is a <button>; don't use div + onclick and then forget the keyboard.
  • Any information conveyed by color alone must have a second channel (copy, shape or motion).
  • Respect prefers-reduced-motion: degrade animations, scroll parallax and auto-playing carousels when reduced motion is requested.
  • Support 200% zoom without losing content; don't hide key buttons inside position:fixed where they vanish with the viewport.

Handoff: give developers something they can use immediately Handoff

  • Export icons as SVG (strip title/meta/comments, use fill="currentColor", keep the viewBox and don't hardcode width/height).
  • Name them in kebab-case with meaning: arrow-left, not icon_12.
  • Give design tokens and code variables the same names (color.bg.subtle); don't call it "light gray 3" in the design file.
  • Deliver all nine states, three sizes and both light and dark themes at once — far more reliable than backfilling half of them later.
